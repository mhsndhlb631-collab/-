## Database boundary

Runtime identity: non-owner, NOSUPERUSER, NOBYPASSRLS; no membership of migration/owner roles. A distinct migrator owns tables. Enable and force RLS on domain tables. Revoke all domain privileges from PUBLIC, anon and authenticated. Grant runtime only reviewed operations; account authority changes must use narrow procedures, never general UPDATE permissions.

DECISION: Migration 0001 creates domain tables with RLS enabled/forced and no allow policies. Runtime SELECT returns no domain rows, and runtime has no domain write privileges. Positive role/scope policies wait for the real Auth gate; default denial is not claimed as a working authorized application. Global pre-auth buckets have no direct runtime access and are reachable only through the fixed SECURITY DEFINER rate-limit function. Its initial local contract is 10 attempts per HMAC bucket per 15-minute fixed window; distributed/network policy acceptance remains pending.

Every request transaction sets local account, workspace and original session context. Missing/invalid context fails closed. Scope uses database account/person relationships, never client role/workspace IDs. Sensitive writes acquire the account lock and recheck state/revocation inside the transaction. No external Auth network request inside an open DB transaction.

The planned session accessor returns only authenticated owner ID and original created_at for the supplied session UUID. It has a fixed search_path, no dynamic SQL and narrowly granted EXECUTE. Deployment is contingent on the real Supabase spike.

Retention: idempotency 7 days, with unfinished Auth operations retained until reconciliation; audit append-only. A service-only cleanup command may expire attempt buckets and completed idempotency rows. No background timer dependency.
