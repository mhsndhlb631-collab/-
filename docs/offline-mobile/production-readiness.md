# مِنهاج — تقرير الإغلاق للإصدار Offline-first / Mobile-first

**النطاق:** المراحل 0–10  
**التاريخ:** 2026-09-12  
**الفرع الآمن:** `codex/offline-mobile-first`

## A. ما تغيّر

- أضيفت قاعدة IndexedDB محلية مع ترقيات إضافية لا تمس العمليات غير المتزامنة.
- أضيف مستودع محلي يفصل البيانات حسب الحساب ومساحة العمل، ويحفظ snapshots والسجلات والـ outbox وخرائط المعرّفات والتعارضات وبيانات آخر مزامنة.
- أضيف محرك أوامر يستخدم UUID ثابتًا كمفتاح idempotency، ويحتفظ بالطلب عند انقطاع الشبكة أو غموض نتيجة الطلب.
- أضيف محرك مزامنة مرتب حسب التبعيات، مع استرجاع العمليات التي توقفت أثناء التنفيذ، وتصنيف دقيق للأخطاء، وbackoff محدود.
- أضيف تجهيز يومي مقصود للبيانات الحرجة حسب الدور، بما فيه 12 جلسة ذات أولوية كحد أقصى؛ لا تنسخ المنصة قاعدة البيانات كاملة.
- أضيف service worker لغلاف التطبيق والملفات الثابتة وصفحة fallback، مع استبعاد كل API والطلبات غير GET من Cache API.
- أضيف مركز مزامنة عربي، وتنقل هاتف حسب الدور، ولوحة «اليوم» موجهة للعمل، ونموذج حضور سريع وشريط حفظ ثابت.
- ضُبطت شاشة الدخول والأحجام من 320px حتى سطح المكتب، مع Cairo وRTL وحواف الهاتف الآمنة.

## C. ما يبقى متصلًا بالشبكة

- أول تسجيل دخول على جهاز جديد، تغيير كلمة المرور، وإنشاء حسابات الدخول.
- التقارير المجمعة الجديدة وCSV والتصدير والتدقيق الكامل؛ يمكن عرض آخر snapshot سبق فتحه فقط حيث وجد.
- إنشاء بنية البرنامج المترابطة بالكامل (قالب ← خطة ← دفعة) ليس مسار P0 للعمل الميداني دون اتصال؛ الأوامر المفردة تحتفظ بطلبها، لكن إنشاء سلسلة جديدة كاملة يحتاج اتصالًا.
- لا توجد عمليات حذف صلب في واجهة المنتج؛ انتقالات الإلغاء والأرشفة هي النموذج المعتمد وتدخل الـ outbox مثل بقية الأوامر.

## D. بنية المزامنة

`واجهة المستخدم → writeJson → IndexedDB transaction (optimistic record + outbox) → SyncManager → API → idempotency_records + transaction → acknowledgement → synced`

تبدأ المزامنة عند فتح التطبيق، وعودة الاتصال، والعودة للواجهة، وتسجيل الدخول، والطلب اليدوي، وكل دقيقة أثناء بقاء التطبيق مفتوحًا. Web Locks تمنع محركين لنفس النطاق من العمل في الوقت نفسه. إذا أغلق المستخدم التطبيق تستأنف العمليات في الفتح التالي؛ لا يعتمد الضمان على Background Sync.

الحالات الحتمية هي: `pending → syncing → synced`، أو عودة إلى `pending` مع موعد retry عند الخطأ المؤقت، أو `failed_*` للخطأ الدائم، أو `blocked_auth`، أو `conflict`. لا تصبح العملية `synced` إلا بعد إقرار HTTP ناجح.

## E. سياسة التعارض

- الحضور والتتبع والتسليمات تستخدم `row_version` أو نسخة الإدخال التي يفرضها عقد الخادم.
- اختلاف السجل نفسه ينتج 409 ويحفظ النسخة المحلية وسجل تعارض، ولا ينفذ last-write-wins.
- تظهر للمستخدم رسالة عربية وخيار استخدام نسخة الخادم عند عودة الاتصال. إسقاط النسخة المحلية يعلّم العملية `discarded` ويحفظ سجل التعارض كتدقيق محلي.
- الأخطاء القابلة للمراجعة تظهر في مركز المزامنة مع إعادة محاولة صريحة بنفس idempotency key.
- اختلاف سجلات طلاب مختلفين يزامن كل سجل بصورة مستقلة.

## F. تحسينات الهاتف

- شريط سفلي من أربع وجهات متكررة و«المزيد»، يختلف للمسؤول والمربي والطالب ولا يعرض مسارات موظفين للطالب.
- رأس ثابت صغير، حواف `safe-area`، مناطق لمس 44px أو أكبر، ومدخلات 16px لتجنب zoom على iOS.
- لوحة اليوم تعرض قرار المسؤول، أو جلسة المربي، أو تكليف/ورد الطالب أولًا؛ المؤشرات والتحليلات تأتي لاحقًا.
- بطاقات مؤشرات أقصر، شبكات عمود واحد للشاشات التشغيلية، وتمرير أفقي مضبوط للتبويبات والجداول التي تحتاجه.
- الحضور بأزرار حاضر/متأخر/بعذر/غائب، مع «تحديد الكل حاضر»، عداد، حالة تغييرات غير محفوظة، وحفظ ثابت فوق شريط الهاتف.
- القيم الثنائية في التتبع تعمل بنقرة واحدة، والاستحقاقات الأقدم وغير المسجلة تظهر أولًا.
- شاشة الدخول تعرض الإجراء كاملًا حتى 320×568 وتحافظ على autocomplete ومدير كلمات المرور.

## G. الاختبارات المنفذة

- 23 ملف اختبار و173 اختبارًا آليًا تشمل التخزين بعد إغلاق القاعدة، الانقطاع، 401، 500، timeout بعد قبول الخادم، exactly-once، ترتيب parent/child، تحويل local ID، التعارض، توقف المزامنة، backoff، تعديلين متتابعين، rapid attendance، ترقية IndexedDB، وعزل metadata حسب النطاق.
- قبول static contract: 19 فحصًا لغلاف PWA، استبعاد API، idempotency، outbox، preloading حسب الدور، الحواف، التنقل، مناطق اللمس، الحفظ الثابت، وautocomplete.
- artifact smoke حقيقي لنسخة الإنتاج المحلية: health/request-id/no-store، readiness المغلقة دون DB، RTL، ملفات PWA، offline fallback وmaskable icon.
- قياس متصفح فعلي عند 320×568، 360×800، 375×667، 390×844، 412×915، 430×932، 768×1024 و1440×900: لا overflow أفقي، RTL صحيح، المدخلات 54px تقريبًا، زر الدخول 57px تقريبًا، والزر كامل داخل أول شاشة في كل مقاس.

## I. تغييرات قاعدة البيانات وواجهات API

لم يضف هذا العمل أي migration ولم يغير مخطط PostgreSQL أو RLS أو Supabase Auth أو أسرار Vercel/Supabase. استُخدمت idempotency و`row_version` والعقود الموجودة. التغيير الإضافي الوحيد في الاستجابة السابقة للعمل هو `workspace_id` في `/me` لعزل المخزن المحلي حسب مساحة العمل.

## J. القيود المعروفة

- لا يستطيع جهاز جديد فتح بيانات لم يزامنها من قبل.
- iOS قد لا يشغّل background sync بعد إغلاق التطبيق؛ يعاود مِنهاج المزامنة عند الفتح/التركيز/عودة الشبكة.
- نطاق preloading متعمد؛ تفاصيل 12 جلسة ذات أولوية فقط، بينما تبقى قائمة الجلسات كاملة حسب استجابة الخادم.
- مركز التعارض الحالي يتيح الرجوع الآمن لنسخة الخادم. الاحتفاظ بالتعديل المحلي بعد تعارض حساس يتطلب مراجعة وإدخالًا جديدًا كي لا يتجاوز نسخة الخادم.
- Cache API لا يخزن استجابات API الحساسة؛ لذلك offline data متاح فقط من IndexedDB بعد مزامنة ناجحة.

## K. قائمة QA اليدوية للإنتاج

1. سجل الدخول مرة متصلًا وانتظر اكتمال «جارٍ تجهيز مساحتك».
2. افتح اليوم والجلسات والتتبع والتكاليف والمتابعة مرة، ثم فعّل وضع الطيران وأعد فتح التطبيق المثبت.
3. افتح جلسة محفوظة، عدّل حضور طالب وتقييمه، واحفظ؛ تحقق من «محفوظة» في مركز المزامنة.
4. أغلق التطبيق وافتحه دون شبكة؛ تحقق من بقاء التعديل.
5. أعد الشبكة، واضغط «مزامنة الآن» إن لم تبدأ تلقائيًا؛ تحقق من وصول العداد إلى صفر.
6. راجع السجل من جهاز ثان وتأكد من عدم إنشاء حضور أو متابعة مكررة.
7. اختبر 401 بإلغاء الجلسة خادميًا؛ يجب طلب الدخول وعدم عرض cache بعد تحقق الرفض.
8. اختبر المسؤول والمربي والطالب عند 320–430px، مع لوحة المفاتيح مفتوحة وشريط الحفظ ظاهرًا.
9. ثبّت PWA ثم افتحه بلا شبكة وتحقق من ظهور الغلاف وصفحة fallback عند غياب snapshot.

## L. حكم الجاهزية

**جاهز للإطلاق المرحلي.** نجح فحص النسخة المنشورة على Vercel عند commit `45fa431`: الصحة وRTL وملفات PWA والغلاف `v2` وmanifest والأيقونات وoffline fallback. طبقة البيانات والـ outbox والمزامنة والإقرار وعدم الازدواج والصلاحيات لم تُضعف، ومسارات P0 الميدانية تعمل دون اتصال بعد التهيئة الأولى. ينبغي بدء الاستخدام بمجموعة صغيرة ومراقبة حالات `failed` و`conflict` في الأيام الأولى قبل التوسع.
