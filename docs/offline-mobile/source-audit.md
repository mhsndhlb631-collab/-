# مِنهاج: تدقيق المصدر وخطة العمل دون اتصال والجوال

**التاريخ:** 2026-09-12  
**الفرع الآمن:** `codex/offline-mobile-first`  
**نطاق التدقيق:** الكود الفعلي، عقود HTTP، خدمات التطبيق، ترحيلات PostgreSQL، واجهات المستخدم، الاختبارات وإعدادات Next.js.

## 1. تدقيق المصدر

### البنية الحالية

| المجال             | الموجود فعليًا                                                                                                     |

### الكيانات والعلاقات

- مساحة العمل ← الأشخاص ← ملفات الطلاب/حسابات الدخول.
- القالب ← نسخة الخطة المنشورة ← الأسابيع وتعريفات الجلسات والتتبع والمحتوى والتكاليف والاختبارات.
- الدفعة ← نسخة خطة مستقلة ← المجموعات.
- الطالب ← enrollment ← عضوية مجموعة بفترة صلاحية.
- المربي ← mentor assignment ← مجموعة بفترة صلاحية.
- جلسة مجدولة ← roster ثابت ← حضور + قيم تقييم معرفة في الخطة + تصحيحات موثقة.
- استحقاق تتبع ← tracking entry ← نسخ ومراجعات.
- تكليف ← submission ← نسخ ومراجعة، واختبار ← result ← نسخ ونشر.
- طالب/التحاق ← attention / case / action / follow-up ← انتقالات حالة وتاريخ مراجعات وأحداث.
- ملخص أسبوع ← revisions واعتمادات موثقة.
- كل عملية حساسة تنتج audit event غير قابل للتعديل.

### الفجوات الحرجة

1. فشل أي طلب ابتدائي أثناء انقطاع الشبكة يجعل التطبيق يبدو مسجل الخروج، حتى لو كانت للمستخدم جلسة وبيانات محلية سابقة.
2. كل قراءة مرتبطة بالشبكة مباشرة، ولا توجد نسخة محلية معزولة حسب الحساب ومساحة العمل.
3. كل كتابة ترسل فورًا. لا توجد outbox دائمة، ولا احتفاظ بالنماذج بعد الإغلاق.
4. مفتاح idempotency ينشأ عند الضغط ثم يضيع مع الطلب؛ لا يمكن ضمان إعادة نفس الطلب بعد إعادة تشغيل المتصفح.
5. لا توجد خريطة client UUID إلى server UUID، لذلك إنشاء أب ثم أبناء دون اتصال غير ممكن حاليًا.
6. لا توجد آلة حالات مزامنة أو backoff أو فصل بين network/timeout و401/403 و5xx وvalidation/conflict.
7. لا يوجد Service Worker؛ manifest وحده لا يتيح إعادة فتح التطبيق دون شبكة.
8. البيانات موزعة بين مكونات تجلب كل منها وحدها، ما يمنع snapshot متسقًا أو delta sync منظمًا.
9. لا يوجد مركز مزامنة أو دليل مرئي على أن الإدخال محفوظ على الجهاز أو وصل للخادم.

## 3. مشكلات تجربة الجوال الحالية

- التطبيق يبدأ من تخطيط سطح المكتب ويخفي الشريط الجانبي خلف drawer عند 800px؛ لا توجد بنية تنقل مخصصة للمهام اليومية على الهاتف.
- شاشة "اليوم" تحتوي بطاقات وإحصاءات أكثر مما يحتاجه أول viewport، بينما الإجراء التالي ليس مهيمنًا بما يكفي.
- نماذج البرنامج والإدارة طويلة وثقيلة، وبعضها يعرض عدة حقول/أقسام دفعة واحدة.
- تسجيل الحضور يستخدم نموذج roster عام؛ لا يوفر إدخالًا سريعًا بإبهام واحد أو إجراء حفظ ثابتًا أسفل الشاشة.
- الحوار/القوائم العائمة مصممة أساسًا لسطح المكتب، ولا يوجد bottom sheet للخيارات السريعة.
- CSS يحتوي طبقات متراكمة من تعديلات dashboard ونقاط توقف متعددة؛ هذا يزيد خطر التعارض والتفاوت بين 320 و430px.
- safe areas غير مطبقة تطبيقًا منهجيًا، ولا يوجد شريط إجراء يحترم `safe-area-inset-bottom`.
- حالات التحميل والخطأ الحالية تعتبر تعذر الشبكة خطأ عامًا، ولا توجد حالة offline طبيعية.
- بعض الأزرار الثانوية تقارب 36–40px؛ العمليات الأساسية على الهاتف تحتاج 44px على الأقل.
- لا يوجد اختبار تلقائي يمنع horizontal overflow في المقاسات المطلوبة.

## 4. البنية المقترحة للعمل دون اتصال

### مصدر البيانات على الجهاز

- IndexedDB بواجهة صغيرة typed ومخطط versioned. لا تخزن كلمات مرور أو cookies أو مفاتيح Supabase.
- قاعدة منفصلة منطقيًا لكل `account_id + workspace_id` داخل المفاتيح، مع حذف/قفل البيانات عند logout مؤكد أو revocation مؤكد.
- جداول محلية مقصودة بدل نسخ قاعدة الخادم كاملة:
  - `scopes`: هوية آمنة وrole ومساحة العمل وآخر تحقق.
  - `snapshots`: payloads من عقود القراءة الحرجة، version، fetchedAt، serverCursor.
  - `records`: إسقاطات قابلة للتحديث الفوري للكيانات P0 مع serverId/localId/baseVersion/syncStatus.
  - `outbox`: الأمر الكامل الآمن، method/path/body، stable idempotency key، dependencies، attempts، nextAttemptAt، status، الخطأ الآمن.
  - `idMap`: ربط UUID المحلي بمعرف الخادم عند الحاجة.
  - `meta`: نسخة المخطط وآخر مزامنة/تنظيف وحالة ترقية.
- ترقية IndexedDB تكون additive؛ لا تحذف outbox أو records المعلقة. أي cleanup يستثني pending/syncing/failed/conflict.

### طبقة التطبيق

1. `OfflineRepository` يقدم قراءة snapshot، optimistic overlay، وإضافة أمر ذريًا إلى outbox.
2. `ConnectivityMonitor` يجمع `online/offline` كإشارة مع نتيجة طلب API فعلية، ويميز offline/degraded/server/auth.
3. `SyncManager` وحيد لكل tab مع قفل Web Locks إن توفر، ويرتب الأوامر حسب dependencies وcreatedAt.
4. كل أمر يحتفظ بنفس `Idempotency-Key` عبر كل المحاولات وإعادة التشغيل.
5. لا يعلّم الأمر synced إلا بعد response ناجح مفهوم وحفظ acknowledgement محليًا.
6. القراءة تبدأ من IndexedDB فورًا ثم تعمل refresh/delta عند توفر الخادم.
7. Service Worker يخزن shell والملفات الثابتة فقط، ويتجنب `/api/*` تمامًا.

## 5. استراتيجية المزامنة والتعارض

### آلة الحالات

`pending → syncing → synced`

- network/timeout/429/5xx: يعود إلى `pending` مع 1s، 3s، 10s، 30s، ثم 60s بحد أقصى أثناء فتح التطبيق.
- 401: `blocked_auth`، لا يسمى offline ولا يعاد بعنف؛ تبقى البيانات غير المرسلة محفوظة.
- 403: `failed_permission`، يتوقف الأمر ويظهر سبب عربي آمن.
- 400/422: `failed_validation`، لا يعاد تلقائيًا.
- 404/410: `failed_missing_dependency` أو تعارض حذف وفق نوع الأمر.
- 409 أو `VERSION_CONFLICT`/`IDEMPOTENCY_CONFLICT`: `conflict` مع نسخة الأساس والتعديل المحلي والنسخة الحديثة عند توفرها.
- إغلاق التطبيق أثناء `syncing`: يعاد إلى `pending` عند الإقلاع إن لم يوجد acknowledgement محفوظ.

### الدمج

- سجلات طلاب مختلفين مستقلة ويمكن مزامنتها بالتوازي المنضبط بعد اعتماد الأب.
- تغييرات متتابعة لنفس الحضور أو القيمة تضغط محليًا إلى النية الأخيرة قبل بدء الإرسال، مع إبقاء الأمر الجاري قابلًا للإثبات.
- الحضور/التقييم/التتبع/التسليم على نفس السجل تستخدم base `row_version`; لا يوجد overwrite صامت.
- انتقالات الحالة (إغلاق جلسة، نشر نتيجة، إغلاق حالة) لا تدمج؛ تعرض مراجعة واضحة عند تغير الخادم.
- الإنشاءات append-only تستفيد من idempotency. عند timeout، يعاد الطلب نفسه بالمفتاح نفسه.
- خيارات التعارض بالعربية: استخدام النسخة الأحدث، إبقاء التعديل المحلي وإعادة بنائه على النسخة الحديثة حين يكون آمنًا، أو مراجعة الاختلاف. القرار النهائي يمر دائمًا بالخادم وصلاحياته.

### مشغلات المزامنة

- بدء التطبيق بعد استعادة snapshot.
- رجوع الاتصال، رجوع tab إلى foreground، نجاح login/session validation، الضغط على "مزامنة الآن"، وبعد إضافة أمر أثناء اتصال صالح، ومحاولة دورية خفيفة أثناء فتح التطبيق.
- Background Sync تحسين اختياري فقط، وليس مصدر الصحة.

## 6. خطة التنفيذ الدقيقة

1. **المرحلة 1:** IndexedDB typed، repository، outbox، UUID، migrations المحلية، monitor، sync manager واختبارات الآلة والحفظ.
2. **المرحلة 2:** Service Worker آمن، offline fallback، تسجيل وتحديث النسخة، headers صحيحة، تحسين manifest واختبار shell.
3. **المرحلة 3:** عقد bootstrap موحد additive وقراءات محلية لشاشة اليوم والمجموعات والطلاب والجلسات والسياق التاريخي المطلوب.
4. **المرحلة 4:** كتابات P0: فتح الجلسة، الحضور والتقييمات، الحفظ والإغلاق المرتب، التتبع، تسليم التكليف، المتابعة/الإجراء، مع optimistic overlay.
5. **المرحلة 5:** retry/backoff، timeout acknowledgement، dependency ordering، client ID mapping عند الحاجة، conflict records وواجهة الحسم.
6. **المرحلة 6:** مؤشر عالمي، حالات "محفوظ على الجهاز"، مركز مزامنة، إعادة المحاولة، quota/upgrade/cleanup الآمن.

## 7. الملفات المتوقع تغييرها

- `package.json` وملف القفل إذا ثبتت الحاجة إلى مكتبة IndexedDB/اختبارها.
- `next.config.ts`, `src/app/layout.tsx`, `src/app/manifest.ts`, `src/app/globals.css`.
- `public/sw.js`, `public/offline.html` وملفات إصدار PWA اللازمة.
- مجلد جديد `src/offline/` للأنواع وقاعدة الجهاز وrepository/outbox/sync/connectivity.
- مكونات `src/app/operations-shell.tsx` ومساحات today/people/distribution/sessions/tracking/learning/followup/journey.
- مكونات جديدة لمؤشر ومركز المزامنة والتنقل السفلي وbottom sheets.
- عقد API إضافي تحت `src/app/api/v1/offline/` وخدمة قراءة خادمية صغيرة إذا احتجنا bootstrap/delta.
- اختبارات `tests/unit/offline-*`, `tests/integration/offline-*`، واختبارات متصفح/قبول جديدة تحت `scripts/` أو `tests/e2e/` وفق الأدوات المثبتة.
- وثائق هذا المجلد وتقارير أدلة QA.

## 8. تغييرات قاعدة البيانات وAPI

- **لا توجد ترحيلات قاعدة بيانات مطلوبة في المرحلة 0.** UUID و`row_version` وrevision history وidempotency موجودة فعليًا.
- التغيير المرجح في API هو **إضافة** bootstrap/delta endpoint محمي يعيد فقط نطاق الممثل الحالي، مع cursor خادمي وpayload محدود. لن تتغير العقود القائمة.
- لن يضاف قبول client-generated IDs إلى أوامر الإنشاء إلا لمسار يحتاج إنشاء أب وأبناء كاملًا دون اتصال ويثبت التدقيق أنه لا يمكن ربطه بالأوامر الحالية. إن لزم، سيكون الحقل اختياريًا، UUID-validated، workspace-scoped، ومحميًا بنفس RLS وidempotency.
- لا حذف صلب ولا تغيير RLS/Auth/أسرار أو إعدادات Supabase/Vercel ضمن هذه الخطة.

## 9. المخاطر وضوابطها

| الخطر                                    | الضابط                                                                                                      |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |

## قرار التصميم

قاعدة الخادم الحالية ناضجة في الصلاحيات والتدقيق والتزامن، لذلك البنية الأنسب هي طبقة محلية رقيقة وموثوقة حول العقود القائمة، لا إعادة كتابة backend. توصية دليل التصميم الآلي بكثافة `8/10` وحركة `2/10` مناسبة لمنتج عمليات؛ تم رفض ألوانه وخطه الإنجليزي المقترحين لأن هوية مِنهاج العربية الحالية تستخدم Cairo والأخضر الداكن والذهبي. سيحافظ التنفيذ على الهوية، ويقلل المساحات ويعطي الأولوية للإجراء التالي وسرعة الإدخال.
